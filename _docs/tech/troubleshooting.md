에듀롬 접속 장애는 단말, 방문 기관의 무선망, 국내외 중계 서버, 소속 기관 인증 서버 가운데 어느 한 구간에서 생깁니다. 이용자가 보는 증상은 「안 된다」 하나지만 원인과 조치할 곳은 구간마다 다릅니다. 이 문서는 기관 담당자가 문의를 받았을 때 볼 증상별 원인과 조치, 구간별 확인 방법, 문의 경로를 정리합니다. 이용자가 직접 따라 할 안내는 공식 웹사이트의 [접속이 안 될 때](https://eduroam.kreonet.net/connect/help/)에 있습니다.

## 문의 접수 시 확인 항목

구간을 좁히려면 아래 정보가 필요합니다. 비밀번호는 받지 않습니다.

| 항목 | 예 | 쓰임 |
|---|---|---|
| 소속 기관과 ID | `hong@example.ac.kr` | realm 과 소속 기관 인증 서버 확인 |
| 접속 장소 | 방문 기관 이름, 건물 · 층 | 방문 기관 무선망 · AP 확인 |
| 일시 | 2026-11-15 14:20 경 | 각 구간 로그 조회 |
| 단말과 운영체제 | 갤럭시, 안드로이드 15 · Windows 11 | 운영체제별 설정 차이 확인 |
| 화면 메시지 | 「인증 문제」, 「인증서를 확인할 수 없음」 | 증상 분류 |
| 단말 무선 MAC 주소 | 해당 SSID 에서 쓰는 주소 | 무선 컨트롤러 · RADIUS 로그 검색 |
| 다른 곳에서의 접속 여부 | 소속 기관에서는 됨 | 구간 좁히기 |

최근 단말은 SSID 마다 무작위 MAC 주소를 씁니다. 단말 설정에 표시되는 기기 고유 MAC 이 아니라 eduroam 네트워크 상세 정보에 표시되는 주소를 받아야 로그에서 찾을 수 있습니다.

## 증상별 원인과 조치

### SSID 가 보이지 않음

| 원인 | 조치 |
|---|---|
| 그 장소에 eduroam 을 송출하지 않음 | 방문 기관 안내에서 서비스 지역 확인 |
| 단말이 지원하지 않는 대역에서만 송출 | 단말의 5 GHz · 6 GHz 지원 여부 확인 |
| AP 장애 | 방문 기관 무선망 담당자에게 위치와 함께 전달 |

### 인증서 경고 또는 연결 거부

CA 를 지정하지 않고 첫 접속 때 「신뢰」를 누른 단말은 대개 CA 가 아니라 그때 받은 서버 인증서를 기억합니다. 서버 인증서는 유효기간이 짧고 인증 어플라이언스가 자동으로 갱신하기도 합니다. 인증서가 바뀌면 단말은 처음 보는 서버로 여겨 접속을 거부하거나 다시 묻습니다.

1. 가짜 AP 일 수 있으므로 소속 기관 안내 페이지에서 CA 와 서버 인증서 변경 공지를 먼저 확인합니다.
2. 바뀌었다면 저장된 eduroam 프로파일을 지우고 다시 설정합니다. 이때 CA 를 지정하면 다음 갱신 때도 그대로 접속됩니다.

CA 나 도메인(서버 이름)을 잘못 넣어도 같은 증상이 납니다. 설정값은 [운영체제별 서버 확인 설정]({{ '/tech/client-validation/' | relative_url }})의 권장 설정 항목을 따릅니다. TOFU(처음 사용 시 신뢰)를 쓴다면 첫 접속은 소속 기관 내부처럼 믿을 수 있는 곳에서 합니다.

### 비밀번호 입력 후 인증 실패

| 원인 | 확인 방법 |
|---|---|
| ID 에 기관 도메인(realm)이 없음 | ID 가 `아이디@기관도메인` 전체인지 확인 |
| 익명 ID 와 ID 의 기관 도메인이 다름 | 두 칸의 `@` 뒤가 같은지 확인 ([익명 ID 와 realm]({{ '/tech/identity-and-realm/' | relative_url }})) |
| 비밀번호 오류 · 만료 · 계정 잠금 | 소속 기관 계정 상태 확인 |
| 에듀롬 전용 계정이 따로 있는 기관 | 포털 계정이 아니라 에듀롬 계정으로 입력했는지 확인 |
| EAP 방식 · 2단계 인증 방식 불일치 | 소속 기관 안내 설정값과 비교 |
| 비밀번호를 바꾼 뒤 옛 설정이 남음 | 저장된 프로파일 삭제 후 재설정 |

### 소속 기관에서는 되지만 다른 기관에서 실패

소속 기관에서 접속되면 계정과 단말 설정은 대체로 정상입니다. 원인은 요청이 소속 기관까지 가는 경로에 있을 가능성이 큽니다.

| 원인 | 확인 방법 |
|---|---|
| 소속 기관 무선망 전용 설정 | 소속 기관에서는 익명 ID 없이도, 또는 기관 SSID 설정으로 접속되는 경우가 있음. eduroam 프로파일을 기관 안내대로 다시 설정 |
| 방문 기관이 다른 기관 요청을 넘기지 않음 | 방문 기관 RADIUS 서버의 프록시 설정과 로그 확인 |
| realm 이 국내 로밍 서버에 등록되지 않음 | 기관 담당자가 NRO 또는 연결된 RO 에 확인 |
| 해외에서만 실패 | 국내 다른 기관에서 시험해 국내 · 해외 구간을 나눔 |

### 접속은 되지만 인터넷이 안 됨

인증은 성공했으므로 방문 기관 무선망의 문제입니다. DHCP 주소 고갈, VLAN 설정 누락, 단말 격리 설정 오류, 방화벽 정책이 흔한 원인입니다. 이용자는 방문 기관 무선망 담당자에게 장소와 시각을 알립니다.

### 접속이 자주 끊김

신호 약화, AP 사이 이동 시 재인증 지연, 단말과 무선 설정(예: 802.11r)의 호환 문제가 주된 원인입니다. 특정 장소에서만 끊기면 방문 기관 무선망, 어디서나 끊기면 단말 쪽을 먼저 확인합니다.

## 구간별 확인 방법

```text
단말 ── 방문 기관 AP · 무선 컨트롤러 ── 방문 기관 RADIUS ── NRO · RO ── 소속 기관 RADIUS (IdP)
 ①            ②                          ③                ④                ⑤
```
{: .diagram}

| 구간 | 확인하는 곳 | 확인 내용 |
|---|---|---|
| ① 단말 | 이용자 | 저장된 프로파일, ID 형식, CA · 도메인 설정 |
| ② 무선망 | 방문 기관 | 무선 컨트롤러의 단말 접속 기록, 인증 요청 송신 여부 |
| ③ 방문 기관 RADIUS | 방문 기관 | 요청 수신과 NRO · RO 로의 전달 여부, 돌아온 응답 |
| ④ 중계 | NRO · RO | realm 라우팅과 전달 기록 |
| ⑤ 소속 기관 RADIUS | 소속 기관 | 요청 도착 여부, 거절 사유(계정 · 비밀번호 · 인증서) |

양 끝에서 좁혀 가는 것이 빠릅니다. 소속 기관 인증 서버에 요청이 도착했는지 먼저 확인하면, 도착하지 않았을 때는 ②~④, 도착했는데 거절했을 때는 ① 또는 ⑤ 로 범위가 줄어듭니다. 거절 응답을 해석하는 방법은 [로밍 운영: 거절과 반복 실패 대응]({{ '/tech/roaming-operations/' | relative_url }})에 있습니다.

로그를 대조할 때는 시각, 익명 ID 의 realm, 단말 MAC 주소(Calling-Station-Id)를 함께 씁니다. 익명 ID 를 쓰는 단말은 중계 구간에서 모두 `anonymous@realm` 으로 보이므로 ID 만으로는 찾을 수 없습니다.

## 문의 경로

| 문의하는 사람 | 문제 구간 | 문의할 곳 |
|---|---|---|
| 이용자 | 계정, 단말 설정, 인증서 | 소속 기관 에듀롬 담당 부서 |
| 이용자 | 방문 기관의 SSID · 신호 · 인터넷 | 방문 기관 무선망 담당 부서 |
| 기관 담당자 | 기관 사이의 전달, realm 등록 | 연결된 RO 또는 NRO |

NRO 문의처는 [대한민국 에듀롬 공식 웹사이트](https://eduroam.kreonet.net)에 있습니다. 기관 담당자가 문의할 때는 위의 「문의 접수 시 확인 항목」과 자기 기관 RADIUS 로그의 해당 기록을 함께 보내면 확인이 빠릅니다.
