에듀롬은 전 세계 어디서든 우리 기관 인증 서버로 로그인 시도를 보낼 수 있는 통로입니다. 에듀롬 비밀번호가 포털 · 메일 · 그룹웨어와 같으면 그 통로가 중요 시스템의 비밀번호를 맞혀 보는 창구가 됩니다. 이 문서는 계정 관리 권고, EAP 방식별 위험, 가능한 공격과 대책을 정리합니다.

## 계정 관리 권고

[운영약관 초안]({{ '/rules/provisions/' | relative_url }}) 3.1.8 의 내용입니다. 초안이므로 권고로 읽습니다.

- 생년월일, 주민등록번호 일부, 학번, 사번, 전화번호처럼 추측할 수 있는 값을 초기 비밀번호로 쓰지 않습니다. `사번1a` 처럼 덧붙이거나 순서를 바꾼 것도 같습니다.
- 모든 사용자에게 같은 초기 비밀번호를 주지 않습니다.
- 1인 1계정으로 발급하고 공용 계정을 두지 않습니다.
- 반복된 인증 실패를 탐지하고 제한합니다.
- 유출이 의심되면 즉시 정지하고 NRO 에 알립니다.

## EAP 방식과 비밀번호 저장

| | PEAP-MSCHAPv2 | TTLS-PAP · GTC | EAP-TLS |
|---|---|---|---|
| 서버에 저장하는 것 | NT 해시 또는 평문 | 솔트 해시 가능 | 비밀번호 없음 (기기 인증서) |
| 개인정보 안전성 확보조치 기준 | 맞추기 어려움 | 맞출 수 있음 | 해당 없음 |
| 서버를 확인하지 않는 단말이 가짜 AP 에 붙으면 | 해시가 넘어감 (해독 가능) | 평문이 넘어감 | 넘어갈 비밀번호 없음 |

어느 방식이든 단말의 서버 인증서 확인이 전제입니다. 설정 방법은 [운영체제별 서버 확인 설정]({{ '/tech/client-validation/' | relative_url }})에 있습니다.

## 포털 비밀번호 공용의 위험

- 에듀롬 SSID 가 있는 곳이면 전 세계 어디서든 우리 기관 인증 서버로 로그인 시도를 보낼 수 있습니다.
- 요청은 방문 기관, RO, NRO, 해외 중계 서버를 거쳐 그대로 도착합니다. 중간 서버는 실패가 많다는 이유로 막지 않습니다([로밍 운영: 거절과 반복 실패 대응]({{ '/tech/roaming-operations/' | relative_url }})).
- 인증 서버에는 공격자의 IP 주소가 보이지 않습니다. 바로 앞 중계 서버 주소와, 바꿀 수 있는 MAC 주소만 보입니다.
- 방문 기관의 무선 장비 가운데 반복 실패 단말을 막지 못하거나 그 기능을 꺼 둔 곳이 많습니다.

## 공격 유형

### 비밀번호 추측

| 공격 | 방법 | 결과 |
|---|---|---|
| 사전 대입 (dictionary) | 흔한 비밀번호 목록을 한 계정에 계속 시도 | 비밀번호 획득 |
| 비밀번호 분사 (password spraying) | 비밀번호 하나를 많은 계정에 조금씩 시도. 계정당 횟수가 적어 잠금에 걸리지 않음 | 약한 계정 여럿 획득 |
| 유출 비밀번호 대입 (credential stuffing) | 다른 사이트에서 유출된 이메일 · 비밀번호 쌍을 시도 | 비밀번호를 재사용한 계정 획득 |
| 계정 잠금 유발 | 일부러 틀려 포털 계정을 잠금 | 포털 · 메일 · 학사 시스템 사용 불가 |

에듀롬 ID 는 대개 이메일 주소와 같아서 공격 대상 목록을 구하기 쉽습니다. 성공한 시도는 정상 로그인과 구분되지 않습니다.

### 인증 정보 탈취

| 공격 | 방법 | 결과 |
|---|---|---|
| 가짜 eduroam AP (evil twin) | 서버 인증서를 확인하지 않는 단말을 끌어들임 | TTLS-PAP 는 평문 비밀번호, PEAP 는 MSCHAPv2 응답 |
| MSCHAPv2 해독 | 가로챈 응답을 오프라인으로 해독. 약한 비밀번호는 사전으로, 강한 비밀번호도 DES 키 탐색으로 | NT 해시 복구 |
| NT 해시 재사용 (pass-the-hash) | 비밀번호를 몰라도 NT 해시로 Windows · Active Directory 인증 | 도메인 계정 장악 |
| 엉뚱한 서버로 전달 | 익명 ID 에 다른 기관 도메인 ([익명 ID 와 realm]({{ '/tech/identity-and-realm/' | relative_url }})) | 다른 기관 서버가 ID · 비밀번호를 받아 봄 |

에듀롬 비밀번호가 Active Directory 비밀번호와 같으면, 가로챈 NT 해시가 곧 도메인 자격 증명입니다.

참고: Moxie Marlinspike · David Hulton, 「Defeating PPTP VPNs and WPA2 Enterprise with MS-CHAPv2」, DEF CON 20 (2012) · [chapcrack](https://github.com/moxie0/chapcrack)

### 저장 정보 유출

- 인증 서버: PEAP 를 위해 NT 해시(솔트 없는 MD4)나 평문을 따로 저장합니다. 이 서버가 뚫리면 포털 비밀번호도 함께 드러납니다.
- 단말: 노트북, 휴대폰, 공용 PC 에 Wi-Fi 비밀번호가 저장돼 있습니다. 분실 · 도난 · 백업이나 관리자 권한 도구로 꺼낼 수 있습니다.
- 비밀번호를 바꾼 뒤: 단말이 옛 비밀번호로 계속 시도하면, 기관의 잠금 정책에 따라 포털 계정까지 잠길 수 있습니다.

## 대응 방안

- 에듀롬 전용 비밀번호를 포털과 따로 둡니다. 영국 Oxford 대학, 스웨덴 Mid Sweden 대학, 체코 CTU, 슬로바키아 TU Košice 등이 이렇게 운영합니다.
- 반복 실패 탐지와 제한은 홈 IdP 가 합니다. 중간의 NRO 는 막을 수 없습니다. 잠금은 포털이 아니라 에듀롬 계정에만 걸리게 합니다.
- 가능하면 EAP-TLS(기기 인증서)를 씁니다. 넘어갈 비밀번호 자체가 없습니다.
- 단말의 서버 인증서 확인과 익명 ID 로 가로채기를 막습니다.
